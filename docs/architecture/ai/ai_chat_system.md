# Nexiom Chat & Conversation System Architecture

## Overview
This document defines the chat layer for Nexiom, enabling users to interact with AI via conversations, view history, and manage chats (similar to ChatGPT-style UX).

---

# 1. Objectives

Provide users with:
- Chat history (left sidebar)
- Create new chat
- View past messages
- Copy messages (user + AI)
- Persistent conversations

---

# 2. Core Architecture

```
UI (Chat Interface)
   ↓
Chat API Layer
   ↓
Conversation + Message Store
   ↓
AI Runtime (Planner → Tool → Transformer → LLM)
   ↓
Response stored + returned
```

---

# 4. Storage Design

## Primary Storage
- PostgreSQL via Drizzle ORM (ai_conversations + ai_messages tables)
- Tenant-scoped composite primary keys for multi-tenancy

## Optional
- S3 (large responses, if needed in future)

Note: Conversation and message persistence is handled internally by the AI module's ChatPersistenceService, not exposed as direct public REST endpoints.

---

# 5. API Design

## 5.1 Submit Chat Message (Job Queue)

```
POST /api/v1/ai/chat
```

Creates a background job and returns jobId for streaming:

Response:
```json
{
  "success": true,
  "jobId": "job_abc123",
  "conversationId": "conv_456"
}
```

---

## 5.2 Stream Job Results (SSE)

```
GET /api/v1/ai/jobs/{jobId}/stream
```

Server-sent events endpoint that streams AI response chunks as they are generated by the worker.

---

## 5.3 Architecture Flow

1. Client sends message via `POST /api/v1/ai/chat`
2. API creates job in SQS queue and returns jobId
3. Client subscribes to `GET /api/v1/ai/jobs/{jobId}/stream` for real-time updates
4. Worker consumes job from queue, processes with AI, publishes chunks to Redis
5. SSE endpoint forwards Redis pub/sub messages to client
6. Worker persists conversation/messages to PostgreSQL via ChatPersistenceService

Request:
```json
{
  "conversation_id": "conv_123",
  "content": "Give me load 215236"
}
```

# 6. AI Integration Flow

## Step-by-step

1. Save user message
2. Call AI runtime (runAIQuery)
3. Stream or wait for response
4. Save assistant response

---

## Example

```ts
await saveMessage({
  role: "user",
  content: query,
  conversation_id,
});

const response = await runAIQuery({ query });

await saveMessage({
  role: "assistant",
  content: response,
  conversation_id,
});
```

# 14. Design Constraints

## Do NOT
- Store raw tool responses
- Store large JSON blobs in messages

## DO
- Store only user + final AI response
- Keep messages lightweight
